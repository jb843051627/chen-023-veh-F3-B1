# 重点营运车辆动态监控模块 口径手册（交接用）

> 这份册子写给接手的人：每一处口径**只在代码里的一处**作答，本册只指路、不另立说法。
> 改代码前先读这份；改完口径必须同步这份，并把对应测试钉上。
> 口径的"唯一答案"永远在代码与测试里，本册是地图，不是第二套口径。

## 二、界次归层四问（只由 `verdict` 一处作答）

屏上、导入、报表都不得另辟第二个能出归层结果的入口。四问的答案：

1. **取数（折算）**：只往界册那一头折。车速 车上报 m/s ×3.6 → km/h；时长 分钟 ÷60 → 小时。
   取数与比数同一把舍法（HALF_UP），与界册列同到**三位小数**。不许多处各舍各的。
2. **请界（在位口径）**：起用那一日已够着（**含当日**）、交班那一日还没到（**不含当日**）。
   交班栏空着的存量界认作一直在位。已停用的不参与；分界数缺格/没越过前头那格的界站不住，不参与。
   补判旧账传旧账自己的那一刻——**历史时点用历史界，不许拿最新版顶替**（报表与归档才对得齐）。
3. **说话（取舍规则）**：在位凑出两条时，先比交班次序（priority 大者说话）；次序相同再比界次代号，
   字典序落在末位的胜出。同一刻只许一个答复，问两遍同一个答复。
4. **归层（压线口径）**：三层只有一套说法，**压线归本层**——
   `[起算,够线)` 提示、`[够线,封顶)` 严管、`[封顶及以上)` 立案；没到起算写"未到起算"。
   一条界都够不上：结论"无可用界"，界次代号与起用日两栏**一并留空**，不许抄旁边那条。

**量程校验只此一处**：负数一律越界；车速过 70 m/s（约 252 km/h）、时长过 1440 分钟（一昼夜）视为采坏。
越界的数**不判档**，与缺参同一路回绝（`verdict` 返回 null，调用方按缺参回绝）。

**判完即归档**：每一次裁决落 `t_veh_run_verdict`（报的什么数、折完多少、归的哪层、哪条界说的话、
问的哪一刻）。日后追溯只翻这一份（`/vehRunLine/archive` 或 `listVerdictArchive`），
**不许事后拿新界重算顶替**。

### 旧名目对照（签名不动的老调用方）

`evaluate / evaluateTop / listAvailable / usable / countAvailable` 留着给老调用方，
**内里与新走法同一把尺**，不再另摆口径：

- 压线同样归高一档；老档序 1..4 依次对应 未到起算/提示/严管/立案。
- 同样只请那一刻的在位界（历史时点不用最新版）；停用、站不住的界同样不参与。
- 同样按说话次序取舍，同一刻问两遍同一个答复。
- 老名目量程：0..100（界册那一头的数），越界回 0；`evaluate` 与 `evaluateTop` 同一把卡尺。
- 查界的道另起名目：`browseRegister`（翻检，含停用/交班，只许看）、`inspectRegister`（体检指名到格）、
  `danglingScreenCodes`（屏挂悬空代号核对）。

## 三、证照到期催办（`TVehDueTaskServiceImpl`）

- 该开口的条目：到了止点时刻（**恰好到期也算**）＋ 待派 ＋ 未留痕删除。
- 时段比较统一走**墙钟字符串**（yyyy-MM-dd HH:mm:ss）：JDBC 时区不对称，直接绑 Date 会整体偏移。
- **窗口判定只在 `runOnce` 一处**：提前量落在 2~5 日窗口内的派出（记"已派出"）；
  窗口外或判据（提前量）缺失的记"分不出"——**判据缺失给兜底结论，不许把异常甩给调用方**。
  一条都够不上返回 0。每条结果都落库，不留待派反复回锅。

## 四、严重报警处置单（`TVehHandleFlowServiceImpl`）

- 环节 0..3（定级/知会/回告/归档）；状态 0未起/1在办/2已封尾。
- **状态只由环节一处推导**（`statusOfStage`）：推进、回退落库时两栏同一次算成，两处记录对得齐。
- 推进一档就是一档，回退一档就是一档（不一竿子退到底）。
- 已封尾为终态：不许再挪、再改、再删。存量两栏对不齐的单，任一栏到顶都按封尾待。

## 五、移交执法核签单（`TVehMoveBillServiceImpl`）

- 档口 0..2（初核/复核/核准）；情形 0在核/1已办结/2已挪回，**只由档口一处推导**。
- 签批一笔计一印（本档已落印数）；凑够算齐线才挪档：一名即可的一票即齐；
  两名须同判的以本档应落人数为准（空着按两名）。挪档即重新计印——应落人数与已落印数两头对得齐。
- 否决即挪回（落"已挪回"）。已办结、已挪回是终态，不许再签、再否、再退。

## 六、月度报警处置核收册（`TVehAlarmBatchServiceImpl`）

- 整册进门一道口子：册头与整册行同一回落库；行数压顶整册退回，库里一行不留。
- 同一册码第二遍递来只照面，不加不减；要改先办撤册再重递。
- 回执三个数各自回库现点现取：送回的＋落库的 ＝ 原有的，接得平。
- 行上结果只许 未勾/收下/退回 三选一；只许从"未勾"落笔，已落成的结果谁也不许覆。
- 往期迁移只朝旧册开（连着两个报送年度还没着落的未勾行）；往期照旧翻得着、一条不许少。

## 七、车辆联网清单页（`TVehBindPageServiceImpl`）

- 立不立得住、还差几项、按属地该见哪几页、页头三数打哪儿来，全归唯一写入/开屏路径作答。
- 还差几项（lack_count）由系统轧出（应联 − 已联），只回显不录入；立页、改口、换层同一套数法。
- 页头三栏与一张一张点出来的页出自同一回点算（窗口计数随名单一起回来），谁也绕不开。

## 八、踩过的坑（别再踩）

1. **等号分两家**：压线归高一档/本层，新旧两处一把尺；不许一处 `<=` 一处 `<`。
2. **时区**：凡是拿时刻跟库里的比，走墙钟字符串，不直接绑 `java.util.Date`。
3. **历史时点重算**：传旧账自己的那一刻；拿最新界顶替，报表和归档就对不上。
4. **停用项**：册里翻得着、屏上列得出，但不许捞去比数；可用判据里混进停用项，判档就不稳。
5. **判据缺失**：给兜底值（0 / 空单 / 分不出 / null 由调用方回绝），不许甩异常。
6. **量程**：越界的数不判档；量程卡尺只在一处，两处各卡各的必有一家漏。
7. **状态与环节**：状态只由环节/档口推导，两处各写各的必对不齐。
8. **取舍规则**：同优先级按界次代号末位；不排定次序，两次问就给两个档。

## 九、改动规矩

1. 口径只在一处作答；要改口径，先改那一处，再同步本册与测试。
2. 新需求另起名目，不往老名目身上挂新参数（老调用方的签名不动）。
3. 每条口径都要有测试钉住（`src/test/java/com/fc/v2/service/` 下四个测试类，共 52 钉）。
4. 跑测试：`mvn test`（不启 Spring，数据层全桩掉）。
